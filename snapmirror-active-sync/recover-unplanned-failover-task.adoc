= Ripristinare da operazioni di failover automatico non pianificato del cluster ONTAP
:hardbreaks:
:allow-uri-read: 
:nofooter: 
:icons: font
:linkattrs: 
:imagesdir: ../media/


[role="lead"]
Un'operazione di failover automatico non pianificato (AUFO) si verifica quando il cluster primario è inattivo o isolato. SnapMirror active sync rileva tali guasti e avvia un failover automatico non pianificato verso il cluster secondario. Il cluster secondario viene convertito in primario (il cluster preferito) e inizia a servire i client. Nota che il rilevamento dei guasti e l'elaborazione del failover possono essere eseguiti solo con l'assistenza di ONTAP Mediator.


NOTE: Dopo il failover automatico non pianificato, è importante eseguire una nuova scansione dei percorsi host così non perdi nessun percorso I/O.



[[reestablish-the-protection-relationship-after-an-unplanned-failover]]
== Ristabilire la relazione di protezione dopo un failover non pianificato

Una volta che il cluster primario originale, ad esempio Cluster A, si è ripristinato, SnapMirror active sync stabilisce automaticamente la protezione nella direzione inversa. Se vuoi ripristinare lo stato originale, rendendo Cluster A il cluster primario preferito, puoi eseguire un failback manuale avviando un'operazione di failover pianificata tramite System Manager o la ONTAP CLI.

[role="tabbed-block"]
====
.System Manager
--
.Fasi

IMPORTANT: Da ONTAP 9.8 a ONTAP 9.14.1, la SnapMirror active sync è denominata SnapMirror Business Continuity (SM-BC).

. Vai su *Protezione > Relazioni* e attendi che lo stato della relazione mostri "InSync".
. Per eseguire un failback e riprendere le operazioni sul cluster di origine, fai clic su image:icon_kabob.gif["Icona delle opzioni di menu"] e seleziona *Failover*.


--
.CLI
--
È possibile monitorare lo stato del failover automatico non pianificato utilizzando `snapmirror failover show` comando.

Ad esempio:

....
ClusterB::> snapmirror failover show -instance
Start Time: 9/23/2020 22:03:29
         Source Path: vs1:/cg/scg3
    Destination Path: vs3:/cg/dcg3
     Failover Status: completed
        Error Reason:
            End Time: 9/23/2020 22:03:30
Primary Data Cluster: cluster-2
Last Progress Update: -
       Failover Type: unplanned
  Error Reason codes: -
....
Puoi monitorare lo stato della relazione di protezione inversa usando il comando  `snapmirror show` sul cluster primario originale.

Ad esempio:

....
ClusterA::> snapmirror show
                                                                               Progress
Source             Destination  Mirror        Relationship   Total             Last
Path         Type  Path         State         Status         Progress  Healthy Updated
-----------  ----  ------------ -------       -------------- --------- ------- --------
vs3:/cg/dcg3 XDP   vs1:/cg/scg3 Snapmirrored  InSync          -         true    -
....
Puoi eseguire un failback al cluster primario originale usando il comando  `snapmirror failover start`.

Ad esempio:

....
ClusterA::> snapmirror failover start -destination-path vs1:/cg/scg3
....
Fare riferimento a. link:https://docs.netapp.com/us-en/ontap-ems-9131/smbc-aufo-events.html["Riferimento EMS"^] per informazioni sui messaggi di evento e sulle azioni correttive.

--
====


[[resume-protection-in-a-fan-out-configuration-after-failover]]
== Riprendere la protezione in una configurazione fan-out dopo il failover

A partire da ONTAP 9.15.1, SnapMirror active sync supporta la riconfigurazione automatica nel ramo fan-out dopo un evento di failover in una relazione SAN. In una configurazione NAS, devi riconfigurare manualmente la relazione di protezione dopo il failover di SnapMirror active sync. Il ramo fan-out asincrono può essere una relazione di gruppo di coerenza o una relazione di volume indipendente. Per ulteriori informazioni, vedi link:interoperability-reference.html#fan-out-configurations["configurazioni fan-out"].

Se utilizzi ONTAP 9.14.1 o versione precedente ed utilizzi un failover sul cluster secondario nella relazione di sincronizzazione attiva di SnapMirror, la destinazione asincrona di SnapMirror non sarà integra. È necessario ripristinare manualmente la protezione eliminando e ricreando la relazione con l'endpoint asincrono di SnapMirror.

.Fasi
. Verificare che il failover sia stato completato correttamente:
`snapmirror failover show`
. Sull'endpoint asincrono SnapMirror, eliminare l'endpoint fan-out:
`snapmirror delete -destination-path _destination_path_`
. Sul terzo sito, crea relazioni asincrone SnapMirror tra il nuovo volume primario SnapMirror Active Sync e il volume di destinazione fan-out asincrono:
`snapmirror create -source-path _source_path_ -destination-path _destination_path_ -policy MirrorAllSnapshots -schedule _schedule_`
. Risincronizzare la relazione:
`snapmirror resync -destination-path _destination_path_`
. Verificare lo stato e la salute della relazione:
`snapmirror show`
